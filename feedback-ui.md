# UI Feedback

## Current Issues and Suggestions for Improvement

1. MUST add the logo at the top of the sidebar.
2. Update padding and spacing for buttons and icons in sidebar. There should be more space between the folder/file icons and the text, and the button to get started on the intro page had no padding at all.
3. Merge the intro page with the main editor view (view while adding and editing notes). This way, you could start taking notes right away without having the `Open Tessellum` button on the intro page. And with this, in the sidebar you can have a button that says `Open Existing Folder` or `Open Project` (or something like that) that opens the file dialog to select a folder to open. This way, you can have the best of both worlds. You can start taking notes right away, and you also have an easy way to open a different folder/project if you want.
  - The UI/UX principle here is to let someone get to where they want to go in the shortest path, with the least friction, and fewest clicks. The one exception in this case would be if you were planning on adding something like a stepper guide or onboarding flow for new users, in which case you could keep the intro page as a separate page that new users see when they first open the app, and then after they complete the onboarding flow, they get taken to the main editor view. But if you don't have plans for an onboarding flow, then merging the intro page with the main editor view would be a good idea.
4. Persist window state. When I set the size of a window of an app, that's the size I like it to be 99% of the time. So when I reopen the app, it's nice if it opens in the same size and position as I had it before. This is a common feature in desktop apps, and it just adds a nice level of polish and thoughtfulness to the user experience when it's implemented. So I would recommend adding this if you have time.
5. When I reopen the app, it opens the last folder I had open, which is good. But it doesn't automatically open the last note I had open. So I have to click on that note in the file tree to open it again. It would be nice if it automatically opened the last note I had open when I reopen the app, as well as the state it was in (it currently does persist the state of the note. It just doesn't open the last note I had open).
6. Visually distinguish the editor area from the sidebar more. Maybe add a subtle background color to the sidebar. You already have a border, which is good. And it's not that it's confusing. It just feels like a distinct section.
7. Above the file tree (at the top, above the folder list), add the name of the current folder/project that is open. If someone is using this for notetaking, it makes it crystal clear and super easy to quickly know which folder/project they are currently working in. It also just makes it feel more polished and complete. Same with coding or other things.
8. Add an additional button at the top of the sidebar for opening a new folder or creating a new project/folder outside of the current folder.
  - Right now, when I open the app, it opens my last opened folder (the one I initially selected when first running the app), which is good. But I also want an easy way to open a different folder or create a new one that isn't in the folder I last had open. So having a button at the top of the sidebar for that would be helpful.
  - Currently, unless I'm mistaken, I can only find a way to create a new file or folder inside the currently open folder. But I don't see a way to create a new folder or open a different folder outside of that. So adding a button for that would be helpful.
  - NOTE: If this app is intended to be a central source of truth for someone's notes, then have a way for a user to easily view all of their folders/projects and easily switch between them.
9. Currently, the `New File` button is a split button, with a chevron that indicates a dropdown option/functionality. But clicking it just opened the modal/dialog for creating a new file. A couple options for improving this:
  - Have it as just a regular button without the chevron, since there isn't currently a dropdown option. This would be the simplest solution.
  - Or, have the button label say `Add New` instead of `New File`, and then have the dropdown options be `File` and `Folder` (and remove the `New Folder` button next to it, as it becomes redundant with this solution).
    - NOTE: With this option, you would have to either make the whole button a dropdown (so clicking anywhere on the button opens the dropdown), or keep the split button, but decide what the default action is when clicking the main part of the button (not the chevron).
10. **BONUS**: Update the app icon (not logo) to be the core icon of the logo instead of the full logo with the name in it. It looks cleaner as an icon on various devices. And your logo/icon is really cool. So I think it's a touch that's worth implementing. I added an example in this repo of what I mean (but I moved the old ones into an `src-tauri/icons/archive` folder. I didn't get rid of them).

## Feature Suggestions and Opportunities for Improvement

### Style Enhancements

1. Themes, themes, themes. Not just dark and light mode. I'm talking about a handful of color themes named like "Warm Paper", "Graphite", "Ocean", etc. This is a way to add a personal feel to the app for users, and makes your app stand out from other similar apps that just have a light and dark mode. You don't need to go crazy with user customization options. Just a handful of well designed themes that users can choose from is enough (like "Warm Paper" just has a warm yellowish background color, for instance).

### Editor Enhancements

1. Add a Markdown-focused WYSIWYG editor. And to make it feel slick and polished and unique (as well as not "in the way" of the writing experience), you could have it as a vertical toolbar along the right side of the editor. A couple good ones to look into would be:
  - [MDX Editor](https://mdxeditor.dev/editor/docs/getting-started)
  - [Toast UI Editor](https://ui.toast.com/tui-editor)
  - NOTE: Quill has been the WYSIWYG gold standard for years. But it isn't really built for Markdown, and it can be a bit heavy and bloated for a simple note-taking app. So I would recommend looking into MDX or Toast UI Editor, as they are both built with Markdown in mind and are more lightweight and customizable.
  - **IMPORTANT:** One of the main benefits of this, and why I suggest it, is that the white space when opening it up goes beyond minimal, to a point where my attention is naturally drawn elsewhere. So having this not only gives users a more polished and slick writing experience, but it also helps to draw their attention to the editor and encourages them to start writing and taking notes right away. If you don't like the idea of the editor, that's fine. But I would at least recommend adding some sort of visual element or design that draws the user's attention to the editor and encourages them to start writing right away, instead of just staring at a blank white space. Minimal and blank are different. Minimal can prevent overwhelm. But blank can often feel overwhelming in its own way, and lead to decision paralysis.
2. Allow users to pin notes to the top of the file tree in the sidebar. This way, they can easily access their most important or frequently used notes without having to scroll through the file tree.
  - As a stretch goal, you could add the ability for users to create and apply tags to their notes, or even just apply color flags to their notes (for instance, if there's a note that still needs work or is a topic I need to review more, then I could flag it with a red color, and then I can easily see which notes need more work or review).
3. Keep the functionality for users to add their own templates to the `.tessellum/templates` directory. But also give users a handful of templates to choose from that are stored in the app's resources that they can choose from and save as a template if they want.
  - Many users won't know what to create as a template, so giving them a starting point will be helpful and give them some inspiration.
  - BONUS: This part is definitely a stretch goal. But you could even have an open source repository of templates that users can contribute to and pull from within the app. So users can see what other people are creating and share their own templates if they want. This would totally separate your app from other note-taking apps and give it a unique community-driven aspect that could be really cool and engaging for users.

### Additional Enhancements

1. Think about the different steak and sizzle features you can add. An example of the steak features would be giving the users the ability to map connected notes. So if you're in one note working on it, it'll show a list of the connected notes at the bottom or somewhere in the UI, and you can click on those connected notes to quickly navigate to them. And a sizzle feature would be something like a graph in the `Graph View` that shows how much time has been spent across each note, or something like that. This would be a fun and unique way to visualize your notes and give users insights into their note-taking habits and patterns. This isn't completely useless. But it is more sizzle than steak. But don't discount the value of sizzle features. They can be a fun and engaging way to keep users coming back to the app and give them a unique experience. The sizzle is what will make people smile during your presentation and think, "Nice..." And it's what non-technical users equate with thoughtful design and attention to detail.
2. Think of what common user behavior will be. Will users likely only ever be working in one note in a session? Or will they maybe be jumping between several notes in a session? If it's the latter, then maybe add a tabbed interface to the editor, so users can have multiple notes open at once and easily switch between them. This would be a more advanced feature, but it could be really helpful for power users who like to work with multiple notes at once. It also just adds a nice level of polish and sophistication to the app that could impress users and make them more likely to stick with it.
